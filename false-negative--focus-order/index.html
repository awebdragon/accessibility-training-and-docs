Accessibility Test Example: Focus Order False Negative

CSS can reorder elements visually without changing the DOM order. This isn't always a problem, and has legitimate use cases, like reversing image + text rows. It becomes a problem when the content has a meaningful sequence and the two orderings (visual and focus/screen reader) tell a different story.

Automated tools won't flag this, but a keyboard or screen reader user experiences the content in DOM order, which may be completely backwards from what's shown on screen.

What's broken: The cards are displayed right-to-left (Update #3 → #2 → #1) due to flex-direction: row-reverse, but the DOM order is #1 → #2 → #3. A sighted user reads the most recent update first. A screen reader or keyboard user encounters them oldest-first, the opposite narrative.

Why it matters here: These updates tell a chronological story. The order changes the meaning, and the order is different between sighted users and screen reader users. A user relying on a screen reader would hear the project kickoff after hearing that development has begun.

Why automated tools miss it: The elements are valid, focusable, and in a logical DOM order. No ARIA is missing. The mismatch between visual and reading order requires a human to judge whether the sequence carries meaning.
