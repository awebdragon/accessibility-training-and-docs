Accessibility Test Example: Meaningful Link Text in Context

Automated scanners check link text against known ambiguous phrases like "click here" or "read more", and correctly flag those. But they can't detect when more plausible-sounding text appears multiple times for different destinations. Five links all reading "View report" look fine to a scanner, even if they go to five completely different reports.

Missed by scanners: repeated plausible text

These links use real, descriptive-sounding text — but the same label points to five different destinations. Most scanners won't flag this.

How scanners check link text: They match against a blocklist of phrases ("click here", "read more", "here", "more", "link"). If your link text isn't on the list, it passes; the scanner has no way to reason about whether the same text is repeated for different destinations.

What's broken in the second row: All five links read "View report" but go to five different destinations. Screen reader users can choose to navigate a page as a list of links without the surrounding content, so any nearby text providing context gets stripped away and they hear the same "view report" for all 5 different destinations.

The fix: Add context via aria-label (e.g. aria-label="View Q1 2025 report") or visually hidden text, or restructure so the heading text is inside the link. There is an argument for making the visible text more differentiated for users with cognitive disabilities, but this requirement is for AAA, not AA, and could be considered best-practice guidance for sites that only need to meet AA.
